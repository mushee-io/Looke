## What the evidence verifier actually checks
- Moderator-only `GET /api/social/ops/m27` requires an unsuspended real session, original M26 authenticated evidence lineage and live PostgreSQL. It reads actual consumed one-use wallet nonces (two cryptographic keys != two human witnesses), M23 signed evidence references, M25 reviews, M26 two-role witness references, real media moderation receipts and pending reports, Points/risk review entries, and M24 incident observations. No user activity or signatures are seeded.
- A `?live=true` call reuses authenticated M21 Cloudinary provider inspection and Ultra EVM/native RPC observations. `?assetKind=token&factory=0x...&tx=0x...` checks canonical Ultra EVM creator coin evidence on chain 18881. `?assetKind=uniq&nativeOwner=...&factoryId=...&tokenId=...` checks current native Uniq ownership. One proof does not establish both. Missing provider credentials and real on-chain records remain blocked.
- M27 explicitly separates *two actually consumed wallet signatures*, *two separately signed role references* and *two independently witnessed real people*. Only the first two can be observed from existing PostgreSQL evidence; no autonomous identity verification or human signoff is claimed.
- Media moderation receipt counters join real approved posts with actual `approve_media` review rows. Approved SQL rows do not prove actual hosted provider ownership/scan content. An operator must separately inspect real provider metadata, content, external moderation results and signed moderation logs.
- `reconcileEntirePointsLedger` paginates all approved Points in a consistent repeatable-read **READ ONLY** transaction and rechecks source eligibility, actor, points, and season. The API has a 250-row cap (no false completion); for more than 250 entries, run the operator CLI with up to 20,000 real records. Any size overflow or source drift is reported as blocked, not quietly accepted. Clean reconciled Points still do not prove anti-sybil human uniqueness or approve token claims.
- Signed M23/M25/M26 evidence-reference hashes prove only recorded key-control events. To independently inspect a real audit report, run `npm run m24:verify-evidence -- --file PATH --evidence-id REAL_UUID --commit EXACT_SHA` and have a separate auditor inspect the actual findings, scope, remediation, current application deployment and operator independence.
