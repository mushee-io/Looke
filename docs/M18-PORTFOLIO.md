# M18 — Ultra portfolio and sourced asset history

**Status: partial, read-only.** M18 brings Ultra EVM testnet balances, native Uniq owner-scoped token holdings and strictly bounded confirmed transfer/creator-launch history into a unified source-labeled dashboard. There are **no USD valuations, PnL, cost basis, actual trades, spend permissions, reconciled creator earnings or comprehensive historical transaction feeds**.

## Implemented

- **EVM portfolio assets:** `GET /api/portfolio/assets?address=<0x>` validates a public EVM address, verifies chain ID **18881**, and pins UOS balance, configured ERC-20 `balanceOf`, `decimals`, `symbol` and contract code reads to the **same observed block**. It checks the block hash again before returning. Each ERC-20 source must be explicitly configured in `LOOKE_PORTFOLIO_TOKEN_ALLOWLIST` (maximum eight unique, nonzero addresses). Missing/invalid configured token code or metadata fails closed instead of silently producing a partial total. Without an allowlist, the response reports only EVM UOS and says **other ERC-20 holdings were not searched**.
- **Native Uniq portfolio:** `GET /api/portfolio/native?account=<native-account>[&cursor=<uint64>]` verifies the fixed native Ultra testnet chain ID, reads up to **20 Uniq IDs** from `eosio.nft.ft::token.b` with the requested native account as scope and validates exact uint64 token/factory IDs and serials. It supports paginated traversal and shows informational head/last irreversible block numbers. Rows are current non-atomic chain table reads, not independently authenticated ownership or complete/irreversible collection snapshots.
- **Bounded onchain activity:** `GET /api/portfolio/activity?address=<0x>` reads only *explicitly configured* token contracts' real ERC-20 `Transfer` logs involving the public address, from the **most recent 250 blocks delayed by 12 confirmations**. Direction and raw transfer values are computed exactly, self-transfers are labeled and duplicate in/out matches deduplicated. Every transfer links to a real transaction hash. No ERC-20 sources configured means no Transfer-history coverage, not zero transactions. Ordinary native UOS transfers, swaps, full historical ERC-20 activity, user cost basis and NFT purchase/sale activity are not yet indexed.
- **Creator-coin activity:** The activity route may additionally display up to 20 **creator-linked factory event records** already stored by M13 only if a configured factory, deployed code, confirmed cursor and current RPC block-hash checkpoint all pass verification. This is launch *event history*, **not current balances or positions**; the existing factory remains unaudited, undeployed in accepted staging, and permissionless.
- **Unified responsive UI:** `components/PortfolioHub.tsx` appears in both the Profile and Activity pages. It offers public-address lookups, a source-labeled EVM UOS/ERC-20 holdings pane, a separate native Uniq page, recent confirmed token transfers and indexed coin creation events, explicit incomplete-source states and explorer links. Stale asynchronous responses are gated to avoid replacing the currently selected account after address/wallet changes. A connected wallet pre-fills its network's address only; an entered address is not proof that the viewer owns it.
- **Pure protections/tests:** `lib/portfolio-guards.mjs` checks source allowlists, addresses, uint256 balances, native uint64 ownership IDs and advancing page cursors, 250-block bounded 12-confirmation history, wallet-related Transfer logs, directions and deduplication; `tests/portfolio-guards.test.mjs` covers edge cases.
- **No new Neon migration:** M18 uses live read-only chain calls and existing M13 source-confirmed creation events; it does not store, credit, value, trade or move assets and it does not insert fabricated testnet holdings.

## Trust and UX boundaries

- The two networks and account systems are **different**. The dashboard explicitly separates Ultra EVM's UOS balance from native Ultra's Uniqs and does not sum token quantities or presume the native account belongs to the EVM session. Real wallet control requires independently verified native/EVM signed challenges and proper network/session binding.
- All token/Uniq data are *observations*, not independent smart-contract provenance verification. The allowlist is operator configuration, **not** a guarantee that ERC-20 token contracts are safe, valued or recognized. Decimals/symbols come from onchain token metadata and can be misleading.
- `/api/portfolio/activity` is a narrow, confirmed-window `Transfer` scanner, not a historical wallet indexer. It deliberately doesn't infer a swap transaction, volume, wallet USD worth, current creator-coin holdings from factory events, native Uniq sales, realized/unrealized PnL or cost basis. Realized royalties remain unverified under M17.
- The native `token.b` scope read is public state and can include legacy limitations. Its `last_irreversible_block_num` is an RPC head indicator, **not proof that the fetched rows are individually irreversible**. There is no native transaction history source, signed ownership proof or cryptographic EVM/native identity binding.
- A single block hash re-read reduces mixed-state EVM snapshots, and 12-block delay reduces shallow-reorg exposure for history, but dishonest RPCs and deep reorgs remain possible. The source provider and contracts need independent review.
- There are **no wallet signatures, approvals, spend instructions, claims, withdrawals, swaps, transfers or mainnet calls** added in M18.

## Acceptance gates

1. Resolve the Vercel team deployment HTTP 403, then validate on protected staging with real EVM/native testnet wallets and account changes, timeouts, stale/rapid requests, HTTP errors and browser accessibility.
2. Individually review and approve real ERC-20 contract addresses (bytecode, deployer, decimals, supply and metadata), configure the portfolio token allowlist and run real balances/transfer checks at independently referenced Ultra EVM testnet blocks with receipts.
3. Verify authentic native Uniq ownership across `token.b`, official Ultra NFT API and independent explorer. Test pagination, legacy `token.a`, sold/transferred tokens, account changes and irreversible history limitations.
4. Build a reliable and properly scoped wallet transaction history indexer with finalized EVM UOS/ERC-20 receipts, native Uniq issuance/listing/buy/sell transfers, block-hash continuity/reorg recovery and independent crosschecks. Backfill historical activity only with known genuine chain evidence.
5. Securely link Looke EVM signed sessions with native Ultra account ownership without inferring identity from a typed name.
6. Implement real cost-basis ledger and only independently sourced market prices/liquidity and fully attributed transfers if adding PnL, earnings, fiat valuation or exposure analytics. Avoid fabricated/estimated USD totals and developer-priced markets.
7. Complete rate limits, RPC quotas, abuse protection, financial accuracy audit and security/privacy/accessibility/load checks before public portfolio launch.

**M18 remains partial** until protected live staging, genuine sourced holdings/transaction receipts, wallet association, full-indexed history and audited accuracy checks succeed.
